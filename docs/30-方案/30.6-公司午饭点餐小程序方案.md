### 缓存配置

| 数据类型 | 缓存有效期 | localStorage key | 说明 |
|---------|-----------|-----------------|------|
| members | 30分钟 | `lunch_cache_members` | 内容缓存，过期后重新拉取 |
| menu | 30分钟 | `lunch_cache_menu` | 内容缓存，过期后重新拉取 |
| recentOrders | 5分钟 | `lunch_cache_recent_orders` | 内容缓存，过期后重新拉取 |
| recentTimestamp | 永久（仅本地） | `lunch_cache_recent_timestamp` | **时间戳本身不会过期被丢弃**；是否刷新取决于与服务端时间戳是否一致 |
| menuTimestamp | 永久（仅本地） | `lunch_cache_menu_timestamp` | 同上 |
| membersTimestamp | 永久（仅本地） | `lunch_cache_members_timestamp` | 同上 |
| monthSummary | 5分钟 | `lunch_cache_month_summary` | 内容缓存 |
| monthlyStats | 30分钟 | `lunch_cache_monthly_stats` | 内容缓存 |
| monthlyStatsTime | 永久（仅本地） | `lunch_cache_monthly_stats_time` | 用于判断 `monthlyStats` 内容缓存是否过期 |
| session | 30分钟 | `lunch_session` | 登录会话缓存 |

> "时间戳缓存永久有效"的含义：本地存储的旧时间戳不会因 TTL 过期被自动清除；实际数据是否刷新，由前端对比服务端最新时间戳决定。外部导入/清库时，云函数必须更新时间戳或清零 `dataTimestamp`，否则前端无法感知数据变化。详见 [30.6-02-技术实现-v2.0.md](30.6-02-技术实现-v2.0.md) 第 8 章。

## 与 v1.0 的主要差异

| 维度 | v1.0 | v2.0（当前代码） |
|------|------|-----------------|
| 时间戳 | 仅有 `recentTimestamp` | 增加 `menuTimestamp`、`membersTimestamp`、`dataTimestamp`、notice 时间戳 |
| 实时同步 | 轮询 `getRecentTimestamp` | 新增 `watchTodayOrders` 实时数据推送 |
| 取消订单 | 仅管理员可取消 | 普通成员可申请取消；可取消自己的待确认订单 |
| 月度统计 | `rebuildMonthStats` 按月聚合 | 支持增量刷新、并发锁定、确定性 `_id` 防重复 |
| 语音点餐 | 计划使用微信同声传译 | 使用原生录音 + 腾讯云 ASR（`lunch_voice`） |
| 菜单排序 | 固定 sortNo 交换 | 基于大众/个人点餐频率的动态排序辅助 |
| 导入导出 | 仅 CSV | 新增 Excel 导入解析；导出上传云存储 |
| 通用模式 | 单租户 `lunch_hp` | 保留 HP 模式 + 通用模式开关（`APP_MODE`） |
| 云函数超时 | 未明确 | `config.json` 统一 20 秒 |
