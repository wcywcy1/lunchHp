## 十六、隔离保障

### 16.1 环境策略

**当前生产环境：**
```
CLOUD_ENV = 'cloud1-d0g9zww8h390b6f41'
```

点餐小程序与账本共用同一个 TCB 环境，通过 `lunch_` 前缀严格区分集合、云函数、存储路径。

### 16.2 命名隔离规则

| 资源类型 | 账本前缀 | 点餐前缀 |
|---------|---------|---------|
| 数据库集合 | 无前缀 | `lunch_` |
| 云函数 | `RevD_` | `lunch_` |
| 云存储路径 | `images/`, `exports/` | `lunch/` |
| localStorage 键 | `ledger_` | `lunch_` |

**硬性规定：**
- ❌ 点餐代码中绝不允许出现 `records`、`accounts`、`families` 等账本集合名
- ❌ 点餐代码中绝不允许出现 `RevD_` 开头的云函数名
- ❌ 点餐代码中绝不允许出现 `ledger_` 开头的 localStorage 键
- ✅ 所有点餐资源必须带 `lunch_` 前缀

### 16.3 云函数超时

所有点餐云函数 `config.json` 统一配置：
```json
{
  "timeout": 20
}
```

### 16.4 代码层面隔离

项目目录独立：
```
d:\family-ledger_RevB\Lunch_HP
```

| 隔离维度 | 机制 | 风险 |
|---------|------|------|
| 源代码 | 独立项目目录 | 零风险 |
| 小程序 | 不同 AppID | 零风险 |
| 数据库集合 | `lunch_` 前缀隔离 | 低风险 |
| 云函数 | `lunch_` 前缀隔离 | 低风险 |
| 云存储 | `lunch/` 路径隔离 | 低风险 |
| localStorage | `lunch_` 前缀 + 不同 AppID | 零风险 |

### 16.5 cloudClient 初始化

## 十七、多组织与运行模式

### 17.1 当前实现：始终支持多组织

当前代码**没有** `APP_MODE` 开关，也不存在“HP 专用 / 通用模式”二选一。行为固定为：

| 场景 | 行为 |
|------|------|
| 无本地 `lunch_session` | 跳转 `pages/group-select`，可创建组织、按组名加入、进入已加入组织 |
| 已有会话 | 进入当前激活组织；首页右上角可跳回选组页切换组织 |
| 所有云函数调用 | `baseRepository.cloudAction` 自动注入 `store.groupId`，回退 `GROUP_ID='lunch_hp'` |
| 组织不存在 | `initGroup` 返回 404，前端清除会话并回到选组页，不会自动“复活”死组 |
| 数据访问 | 所有 `lunch_*` 集合客户端不可直接读写；所有业务数据通过云函数访问；多组织隔离依赖云函数的 `groupId`/成员/角色校验 |
| 入组规则 | **开放入组是确认的产品规则**：知道组织名即可通过 `joinGroupByName` 加入，不设邀请码、审批或申请流程 |

### 17.2 组 ID 与默认回退

```typescript
export const GROUP_ID = 'lunch_hp'   // 仅默认回退
export const ACTIVE_GROUP_ID_KEY = 'lunch_active_group_id'
```

`lunch_hp` 只是默认值。新建组 ID 为 `lunch_{timestamp}_{random4}`；用户实际使用哪个组织由本地 `lunch_active_group_id` 与 `store.groupId` 决定。

### 17.3 创建/加入/切换组织

1. 无本地会话时启动进入 `pages/group-select/index`；有会话时直接进首页
2. 用户可：
   - 查看已加入组织（`listJoinedGroups`）
   - 输入组名加入（`joinGroupByName`，组名全局唯一）
   - 创建新组织（`createGroup`，组名全局唯一）
3. 选择组织后的真实调用链：`clearFreshnessCache() → clearAllCache()（含 session）→ resetStore() → setActiveGroupId(target) → startInit()（lunch_menu.initGroup，仅校验存在）→ joinGroup → 保存 member/session → 首页 onShow freshness（getDataTimestamps）`
4. 主动切换**不调用 `getInitData`**；`getInitData` 仅用于冷启动无 member 和恢复备份后的重新加载
5. `joinGroupByName` 创建新成员后更新 `membersTimestamp`，同组其他客户端通过 freshness 感知成员变化
6. 所有云函数调用通过 `baseRepository.cloudAction` 自动注入当前 `groupId`

### 17.4 历史数据安全

- 切换组织不会删除任何数据
- 所有数据查询都带 `groupId` 过滤；安全边界在云函数的 `groupId`/成员/角色校验
- 重新创建同名组会生成新的 `groupId`，不会恢复已删除组织的旧数据；仅切换组织时原有数据仍按 `groupId` 隔离保留
- 旧组织延迟缓存写入通过 `_cacheGeneration` + `groupId` 双校验丢弃；客户端不使用 `Collection.watch`，切换后由首页 `onShow` freshness 和管理页 `loadData` 重新加载
- 创建者可调用 `deleteGroup` 彻底删除组织；该操作会清除订单、菜单、成员、个人统计、月度统计、审计日志、下单锁、备份记录及备份文件，并删除仅属于该组织的头像文件（仍被其他组织引用的头像保留），最后删除组文档，不可恢复

## 十八、新项目启动指南

### 18.1 从现有项目部署的步骤

1. 确认 `src/constants/appConfig.ts` 中的 `CLOUD_ENV`
2. 部署 `wxcloud/functions/` 下 4 个云函数（`lunch_menu`、`lunch_order`、`lunch_backup`、`lunch_voice`），其中 `lunch_backup` 需要同时上传 `config.json` 中的 `weeklyBackup` 定时触发器
3. 首次打开小程序进入选组页：**由用户手动创建组织**（`createGroup`）或加入已有组织；`initGroup` 只校验组织存在，不会自动建组
4. 管理员录入菜单、设置停止接单时间、指定管理员

## 十九、与 v1.0 的差异总结

| 项目 | v1.0 | v2.0 |
|------|------|------|
| 运行模式 | 单租户 lunch_hp | 多组织始终开启，选组页创建/加入/切换 |
| 实时同步 | 轮询 | 客户端不使用 `Collection.watch`；onShow + freshness + 下拉/操作后刷新 |
| 取消机制 | 仅管理员 | 普通成员可取消待确认/申请取消已确认 |
| 月度统计 | 简单 rebuild | 增量刷新 + 并发占位 + 删除标记 |
| 语音 | 微信同声传译 | 腾讯云 ASR |
| 导入 | CSV | CSV + Excel |
| 通知 | 无 | 停止接单时间本地提示（非组通知） |
| 云函数超时 | 未明确 | 统一 20 秒 |
| 备份恢复 | 未明确 | 分片恢复协议 v2 + 安全快照 + 维护锁 |
