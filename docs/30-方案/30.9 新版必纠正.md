# 30.9 新版必纠正

## 1. groupId 回退 'lunch_hp' 已移除 ✅

### 原问题

三个云函数入口均有回退逻辑：

```js
GROUP_ID = event.groupId || 'lunch_hp'
```

- 单组织时代的遗留，仅为兼容旧版客户端
- 如果前端异常未传 `groupId`，数据会**悄悄写入 lunch_hp**，导致数据串组
- 静默写错比直接报错更难排查

### 已应用的修正

**云函数**（3 个文件）：回退改为必传校验

```js
GROUP_ID = event.groupId
if (!GROUP_ID) return { code: 400, msg: 'missing groupId' }
```

涉及文件：
- `wxcloud/functions/lunch_menu/index.js` — main 入口
- `wxcloud/functions/lunch_order/index.js` — main 入口
- `wxcloud/functions/lunch_backup/index.js` — main 入口

**前端** `baseRepository.ts`：去掉硬编码 `GROUP_ID` 常量回退，改为多级恢复链路

```ts
const groupId = store.groupId || getActiveGroupId()
if (!groupId) {
    uni.reLaunch({ url: '/pages/group-select/index' })
    return Promise.reject(new Error('groupId missing'))
}
```

### groupId 恢复链路

```
app启动 → store.groupId（内存）有值？
  ├─ 是 → 正常使用
  └─ 否 → getActiveGroupId()（localStorage）有值？
            ├─ 是 → 恢复 groupId，正常使用
            └─ 否 → 跳转 group-select 页
                      → listJoinedGroups（按 openid 查数据库）
                      → 有组？展示列表，用户点选进入
                      → 无组？展示创建/加入界面
```

即使本地缓存全部丢失，用户也不会丢数据——数据库里按 openid 一定能找回组织。

## 2. createGroup 中 db.serverDate() 不得复用

### 现状（已修复）

原代码 `const now = db.serverDate()` 在组和成员两次 `add` 中复用，导致第二次写入失败，产生"有组无成员"的脏数据。

### 修正（已应用）

组和成员各自独立调用 `db.serverDate()`，不再共享变量；补上 `status: 'active'`。

### 规则

所有云函数中，`db.serverDate()` 每次使用必须独立调用，禁止赋值给变量后复用。

## 4. createGroup 创建者应为 active + creator

### 现状（已修复）

原代码缺少 `status: 'active'`，导致创建者可能被视为 pending。

### 规则

`createGroup` 写入的创建者成员必须同时具备：
- `role: 'creator'`
- `status: 'active'`

与 `joinGroup` / `joinGroupByName` 中 `lunch_hp` 的自动通过逻辑对齐。
