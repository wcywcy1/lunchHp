## 十四、隔离保障

### 14.1 环境策略

**测试阶段：独立环境**
- 点餐小程序使用独立的云开发环境，与账本完全隔离
- 目的：开发调试期间互不干扰，数据零风险

**生产阶段：共用环境，命名隔离**
- 点餐和账本共用同一个 TCB 环境
- 通过 `lunch_` 前缀严格区分集合、云函数、存储路径
- 安全规则限制访问权限，防止越界

```
TCB 环境（生产共用）: cloud1-d4ghy8qey61f8214d
├── 账本集合: records, accounts, members, families, monthly_stats...
├── 点餐集合: lunch_orders, lunch_menu, lunch_members, lunch_groups, lunch_monthly_stats, lunch_backups
│
├── 账本云函数: RevD_record, RevD_user, RevD_stats...
├── 点餐云函数: lunch_menu, lunch_order, lunch_backup
│
├── 账本存储: images/, exports/...
└── 点餐存储: lunch/avatar/, lunch/photos/, lunch/exports/
```

### 14.2 命名隔离规则（生产阶段核心保障）

| 资源类型 | 账本前缀 | 点餐前缀 | 规则 |
|---------|---------|---------|------|
| 数据库集合 | 无前缀 | `lunch_` | 点餐所有集合必须以 `lunch_` 开头 |
| 云函数 | `RevD_` | `lunch_` | 点餐所有云函数必须以 `lunch_` 开头 |
| 云存储路径 | `images/`, `exports/` | `lunch/` | 点餐所有文件存储在 `lunch/` 目录下 |
| localStorage 键 | `ledger_` | `lunch_` | 点餐所有本地缓存以 `lunch_` 前缀开头 |
| 云函数 action | 账本业务 action | 点餐业务 action | 不共用 action 名 |

**硬性规定：**
- ❌ 点餐代码中绝不允许出现 `records`、`accounts`、`families` 等账本集合名
- ❌ 点餐代码中绝不允许出现 `RevD_` 开头的云函数名
- ❌ 点餐代码中绝不允许出现 `ledger_` 开头的 localStorage 键
- ✅ 所有点餐资源必须带 `lunch_` 前缀

### 14.3 安全规则隔离

在云开发控制台配置数据库安全规则，确保点餐集合只能被点餐云函数访问：

```json
// lunch_orders 安全规则示例
{
  "read": "auth.openid != null",
  "write": "auth.openid != null"
}
```

- 所有 `lunch_` 集合的安全规则独立配置
- 账本集合的安全规则不受影响
- 即使前端代码误调用，安全规则也会拦截

### 14.4 代码层面隔离

```
d:\family-ledger_RevB\
├── mobile.B\          ← 账本项目（当前）
└── lunch-order\       ← 点餐项目（全新目录）
```

| 隔离维度 | 机制 | 风险 |
|---------|------|------|
| 源代码 | 独立项目目录 | **零风险** |
| 小程序 | 不同 AppID | **零风险** |
| 数据库集合 | `lunch_` 前缀隔离 | **低风险**（需严格遵守命名规则） |
| 云函数 | `lunch_` 前缀隔离 | **低风险**（需严格遵守命名规则） |
| 云存储 | `lunch/` 路径隔离 | **低风险**（需严格遵守路径规则） |
| localStorage | `lunch_` 前缀隔离 | **零风险**（不同 AppID 天然隔离） |

### 14.5 复用代码的边界

从账本复用的代码仅限**架构模式和工具函数**，不涉及任何业务逻辑：

| 复用项 | 复用方式 | 是否涉及账本数据 |
|--------|---------|:---------------:|
| baseRepository 模式 | 复制源码到新项目，修改环境ID | ❌ |
| cloudClient 初始化 | 复制源码，**改为新环境ID**（测试）或**保持同一环境ID**（生产） | ❌ |
| monthly_stats 模式 | 参考架构，在新环境重建，集合名改为 `lunch_monthly_stats` | ❌ |
| 导出 CSV 工具函数 | 复制源码，改表头 | ❌ |
| FilterPanel 组件 | 复制源码到新项目 | ❌ |
| CheckboxPicker 组件 | 复制源码到新项目 | ❌ |

**关键：所有复用代码在测试阶段指向独立环境ID，生产阶段指向同一环境ID，但只访问 `lunch_` 前缀的资源。**

### 14.6 部署隔离

```
测试阶段：
  账本云函数部署：在 mobile.B 目录下右键上传 → cloud1-d4ghy8qey61f8214d
  点餐云函数部署：在 lunch-order 目录下右键上传 → <测试环境ID>

生产阶段：
  账本云函数部署：在 mobile.B 目录下右键上传 → cloud1-d4ghy8qey61f8214d
  点餐云函数部署：在 lunch-order 目录下右键上传 → cloud1-d4ghy8qey61f8214d（同一环境）
```

- 不同项目目录，部署操作互不影响
- 即使误操作，命名前缀也能防止覆盖

### 14.7 cloudClient 初始化

```javascript
// constants/appConfig.js
export default {
  // 测试阶段：独立环境
  // 生产阶段：与账本共用环境
  cloudEnv: '<环境ID>',

  defaultGroupId: 'lunch_hp',
  appName: '我要干饭',
  enableSceneJoin: false
}
```

```javascript
// cloudClient.js（点餐项目）
import config from '@/constants/appConfig.js'

wx.cloud.init({ env: config.cloudEnv })
```

**环境ID切换方式：**
- 测试阶段：`cloudEnv` 填独立测试环境ID
- 生产阶段：`cloudEnv` 改为账本的云环境ID `cloud1-d4ghy8qey61f8214d`
- 只需改一个配置项，无需修改代码

## 十五、多租户配置指南（未来扩展）

### 15.1 核心思想

**一套代码 + 一个云环境 + 一个开关**，即可服务多个组织。所有组织数据天然隔离（通过 `groupId` 字段），互不影响。

### 15.2 配置文件

```javascript
// constants/appConfig.js
export default {
  // 默认组织标识（无 scene 参数时使用）
  defaultGroupId: 'lunch_hp',

  // 小程序名称（导航栏标题）
  appName: '我要干饭',

  // 是否启用扫码入组
  // false = 单租户模式：所有人固定加入 lunch_hp
  // true  = 多租户模式：从二维码 scene 参数读取 groupId，自动创建新组
  enableSceneJoin: false
}
```

### 15.3 启用多租户（只需改一个开关）

将 `enableSceneJoin` 改为 `true`，其余代码无需修改。

**工作流程：**

1. **扫码进入** → 小程序解析二维码 `scene` 参数（如 `scene=lunch_tencent`）
2. **joinGroup 云函数**：
   ```javascript
   // 从 scene 解析 groupId，无 scene 则用默认值
   const groupId = scene || config.defaultGroupId

   // 检测组是否存在，不存在则自动创建
   const group = await db.collection('lunch_groups').doc(groupId).get()
   if (!group) {
     await db.collection('lunch_groups').add({
       _id: groupId,
       name: scene ? '新组织' : 'HP午饭',
       creatorId: openid,
       createdAt: new Date()
     })
   }

   // 后续所有操作都带 groupId 过滤
   ```
3. **所有数据查询**都带 `where({ groupId })`，天然隔离

### 15.4 为其他组织生成二维码

每个组织一个专属二维码，`scene` 参数即为 `groupId`：

```
组织A: scene=lunch_tencent
组织B: scene=lunch_alibaba
组织C: scene=lunch_bytedance
```

微信云开发支持生成带参小程序码，`scene` 值最大 32 字符。

### 15.5 历史数据安全

| 场景 | 影响 |
|------|------|
| `enableSceneJoin = false`（当前） | 所有人加入 `lunch_hp`，历史数据不受影响 |
| `enableSceneJoin = true`（开启后） | 新组织通过专属二维码加入自己的组，`lunch_hp` 数据完全隔离 |
| 删除某个组织记录 | 仅影响该组织的 `lunch_groups` 记录，数据（members/orders/menu）仍保留在库中 |
| 重新创建同名组 | 历史数据自动恢复关联（`groupId` 匹配） |

**关键保障：** 所有数据查询都带 `groupId` 过滤，任何组织的操作都不会越界。

## 十六、新项目启动指南

### 16.1 从账本项目独立出来的步骤

```
步骤1：复制整个 mobile.B 目录到新文件夹
        例如：d:\lunch-order\

步骤2：修改 manifest.json
        - 修改 AppID（微信开放平台新建小程序）
        - 修改应用名称为"我要干饭"

步骤3：修改 constants/appConfig.js
        - cloudEnv 改为新云环境ID（测试阶段用独立环境）
        - defaultGroupId 保持 lunch_hp（或自定义）

步骤4：新建云环境，部署云函数
        - 在微信云开发控制台新建环境
        - 部署 wxcloud/functions/ 下所有云函数

步骤5：初始化 lunch_groups 表
        - 首次打开小程序时，自动调用 initGroup 检测并创建
        - 无需手动在云开发控制台创建

步骤6：删除账本相关引用
        - 删除 services/repositories/ 下不需要的文件
        - 删除 components/ 下不需要的组件
        - 删除 hooks/ 下不需要的文件
        - 保留：baseRepository.js、useDataExport.js
```

### 16.2 与账本的彻底切断清单

| 检查项 | 测试阶段 | 生产阶段 |
|--------|---------|---------|
| AppID | 改为新小程序的 AppID | 同左 |
| 云环境ID | 独立测试环境ID | 改为账本环境ID `cloud1-d4ghy8qey61f8214d` |
| 云函数名 | 以 `lunch_` 开头 | 同左（同一环境也不冲突） |
| 数据库集合 | 以 `lunch_` 开头 | 同左（同一环境也不冲突） |
| localStorage 前缀 | 改为 `lunch_` 前缀 | 同左（不同AppID天然隔离） |
| 云存储路径 | 改为 `lunch/` 路径 | 同左 |
| 日志/埋点 | 删除账本相关的日志上报 | 同左 |
| 分享文案 | 改为"我要干饭"相关 | 同左 |

### 16.3 命名规范

**变量/函数命名：**
- 所有业务相关变量以 `lunch` 或 `order` 为前缀
- 不使用 `ledger`、`family`、`bill` 等账本相关词汇
- 云函数名：`lunch_menu`、`lunch_order`、`lunch_backup`

**文件命名：**
- 页面：`pages/index/index.vue`、`pages/menu/menu.vue`
- 组件：`components/menu/MenuItem.vue`
- hooks：`hooks/useMenu.js`、`hooks/useOrder.js`
- 常量：`constants/appConfig.js`、`constants/orderStatus.js`

**禁止：**
- ❌ 不要保留 `ledgerRepository.js`
- ❌ 不要保留 `useLedger.js`
- ❌ 不要保留账本相关的 console.log
