> 全局常量速查表见 [30.6-公司午饭点餐小程序方案.md](30.6-公司午饭点餐小程序方案.md)

## 一、需求总览

| 项目 | 说明 |
|------|------|
| 名称 | 我要干饭 |
| Logo | `docs/hp logo.png` |
| 用户 | HP 公司约 20 名同事 |
| 场景 | 每天午饭点餐，管理员确认后下单 |
| 入组 | 打开即进，自动加入点餐组（默认 `groupId=lunch_hp`），首次弹出姓名输入框（可跳过） |
| 数据隔离 | 与账本共用 TCB 环境，所有集合/云函数/存储路径以 `lunch_` 前缀隔离 |
| 运行模式 | `APP_MODE='hp'` 固定进 lunch_hp；`APP_MODE='general'` 支持创建/加入多个组织 |

### 核心功能

| 模块 | 功能 | 说明 |
|------|------|------|
| **用户进入** | 打开即进 | 自动加入点餐组；首次弹出姓名输入框（可跳过） |
| **首页** | 当日日期 | 显示年月日 |
| **首页** | 月度汇总 | 当月总订单数 |
| **首页** | 今日点单 | 显示今日点单明细 + 状态标签（待确认/已确认/已取消） |
| **首页** | 个人信息 | 点击右上角头像/姓名 → 弹出编辑自己姓名的弹窗 |
| **首页** | 实时同步 | 所有在线成员通过 `watchTodayOrders` / `watchGroupNotice` 实时收到今日订单、通知变化 |
| **菜单页** | 餐品列表 | 序号、供应商、餐品（价格仅管理员端显示）、照片(可选)、可见/隐藏状态 |
| **菜单页** | 表头筛选 | 供应商/餐品名筛选，联动过滤可选项 |
| **菜单页** | 点餐下单 | 选择菜品提交，提交后不可自行修改；仅显示可见菜品 |
| **菜单页** | 帮人点餐 | 可选择同事代为下单，所有人可用 |
| **菜单页** | 语音点餐 | 长按麦克风录音 → 腾讯云 ASR 识别 → 提取关键词筛选菜品 |
| **菜单页** | 菜单编辑（管理员） | 添加/编辑/删除/切换可见/按供应商批量显隐 |
| **统计页** | 年度/月度统计 | **仅管理员可见**；柱状图（带金额标签）+ 供应商占比饼图（带金额） |
| **统计页** | 筛选 | **仅管理员可用**；年份 + 月份 + 点餐人 + 供应商 |
| **统计页** | 筛选详单 | **仅管理员可见**；年月日\|姓名\|餐品\|金额\|供应商 |
| **统计页** | 柱状图下载 | **仅管理员可用**；分月聚合数据可下载 |
| **管理页（pages/data）** | 订单管理 | 待确认列表 + 批量确认；已确认列表按供应商分组 |
| **管理页** | 取消申请 | 查看普通成员对已确认订单的取消申请 |
| **管理页** | 成员管理 | 查看成员列表，编辑任意成员姓名，设置管理员，删除成员 |
| **管理页** | 下载确认单 | 已确认订单下载，可选按供应商分文件或一并下载 |
| **管理页** | 导入导出 | 导出清单；导入 CSV/Excel（订单/菜单/成员） |
| **管理页** | 通知公告 | 设置/清空组通知 |
| **管理页** | 数据备份 | 手动/自动备份、恢复、全量导出、清空数据 |
| **权限** | 统计页/管理页仅管理员可见 | 点餐者 TabBar 不显示统计/管理入口 |

```
角色：
├── 创建者（建组人）       → 全部权限 + 可指定管理员
```

## 三、TabBar 配置

**管理员视角：**
```
[首页]    [菜单]    [统计]    [管理]
```

**点餐者视角：**
```
[首页]    [菜单]
```

CustomTabBar 根据 `role` 动态渲染：
- 创建者/管理员：4 个 Tab（首页、菜单、统计、管理）
- 普通点餐者：仅 2 个 Tab（首页、菜单），统计/管理 Tab 不显示
- 统计页和管理页 `onShow` 均有权限守卫，非管理员会跳转回首页

## 四、数据模型

### 4.1 lunch_groups（点餐组）

> 默认 `_id = "lunch_hp"`。通用模式下可创建新组，`_id` 由系统生成。

```
_id               // 固定 "lunch_hp" 或系统生成
groupId           // 同 _id
name              // 组名，如"HP午饭"
creatorId         // 创建者 openid
qrcode            // 入口二维码场景值（保留，暂不使用）
notice            // 组通知公告
createdAt         // 创建时间
menuTimestamp     // 菜单最后更新时间
membersTimestamp  // 成员最后更新时间
ordersTimestamp   // 订单最后更新时间（dataTimestamp 语义）
dataTimestamp     // 月度统计最后重建时间；0 表示需要重建
```

### 4.2 lunch_members（成员）

```
_id
name              // 姓名（用户输入，可为空）
nickName          // 微信昵称（自动获取，name为空时的显示名）
avatar            // 头像 fileID（云存储路径，用户主动选择后上传）
openid            // 微信 openid（虚拟成员为空，登录后补上）
role              // creator / admin / member
isVirtual         // 是否虚拟成员（true=帮人点餐时创建 / false=已登录）
privacyAgreed     // 是否同意隐私协议
joinedAt          // 加入时间
lastOrderedAt     // 最后点餐时间（用于成员排序）
```

**姓名显示规则：**
- `name` 有值 → 显示 `name`
- `name` 为空 → 显示 `nickName`（微信昵称）
- 前端统一用 `displayName = name || nickName`

**虚拟成员规则：**
- 帮人点餐时 [＋新增同事] 创建的成员，`openid` 为空，`isVirtual = true`
- 虚拟成员在成员列表中显示灰色标记"未登录"
- 虚拟成员绑定微信有两个入口（所有人可用，不限管理员）：
  - **入口1：登录时自动匹配** — `joinGroup` 按 name 精确匹配虚拟成员，弹出确认弹窗
  - **入口2：首页手动关联** — 点击右上角头像/姓名 → 弹窗中增加"关联已有记录"选项

**虚拟成员绑定流程（入口1 — 自动匹配）：**
- 打开小程序时，`joinGroup` 检测到同名虚拟成员（name 精确匹配）
- 弹出确认弹窗：
  ```
  ┌─────────────────────────┐
  │  关联点餐记录            │
  │                          │
  │  是否关联到之前"张三"的  │
  │  点餐记录？              │
  │                          │
  │  [否，创建新成员] [是，关联]│
  └─────────────────────────┘
  ```
- 选"是" → 将虚拟成员 `openid`/`nickName` 补上，`isVirtual=false`，删除当前新建成员
- 选"否" → 创建新成员，不合并

**虚拟成员绑定流程（入口2 — 手动关联）：**
- 首页右上角点击头像/姓名 → 弹窗底部增加"关联已有记录"按钮
- 点击后显示所有虚拟成员列表，选择一个 → 弹出确认弹窗（同上）
- 适用场景：登录时名字没匹配上，后来自行关联

**头像处理（与账本一致）：**
- 微信已废弃 `wx.getUserProfile`，无法自动获取微信头像
- 使用 `<button open-type="chooseAvatar" @chooseavatar="onChooseAvatar">` 方式
- 用户主动点击"选择微信头像"按钮 → 获取临时路径 → 上传到云存储 `lunch/avatar/` 目录 → 存储 fileID
- 未设置头像时，显示姓名首字的彩色圆形占位符

**菜单照片上传流程：**
- 管理员添加/编辑菜品时，可点击"添加照片"按钮
- 调用 `wx.chooseMedia` 选择图片 → 获取临时路径
- 上传到云存储 `lunch/photos/` 目录（文件名格式：`menu_{timestamp}_{random}.jpg`）
- 存储 fileID 到 `lunch_menu.photo` 字段
- 删除菜品时，同时调用 `wx.cloud.deleteFile` 删除对应云存储文件
- 照片为可选项，`photo` 字段为空时不显示图片

### 4.3 lunch_menu（菜单）

```
_id
name              // 餐品名
supplier          // 供应商
price             // 价格（数字）
photo             // 照片 fileID（可选，为空则不显示）
sortNo            // 序号（排序用，整数，间距10便于插入）
visible           // 是否可见（true=可见 / false=隐藏）
orderCount        // 累计点餐次数（用于动态排序）
lastOrderedAt     // 最近点餐时间（用于动态排序）
createdAt         // 创建时间
```

**visible 字段规则：**
- `true`：所有用户可见可点
- `false`：仅管理员可见，显示在可见菜品下方，灰色标记
- 管理员可将可见菜品设为不可见，也可将不可见菜品恢复为可见
- **不可见菜品永远排在可见菜品下方**，上移操作不可跨越可见/不可见分界线

### 4.4 lunch_orders（订单）

## 五、订单状态机

### 5.1 状态流转

```
                    点餐者提交
  （未下单） ──────────────▶ pending（待确认）
                                 │
                    管理员确认    │    管理员取消 / 自动过期 / 自己取消
                 ┌───────────────┘──────────────┐
                 ▼                              ▼
          confirmed（已确认）           cancelled（已取消）
                 │
     普通成员申请取消
                 │
                 ▼
     cancelRequested=true（等待管理员处理）
                 │
        管理员同意取消 ───────▶ cancelled
        管理员拒绝取消 ───────▶ cancelRejected=true，恢复 confirmed
```

### 5.2 状态字段定义

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | `pending` | 待确认，刚提交，管理员未确认 |
| `status` | `confirmed` | 已确认，管理员已确认 |
| `status` | `cancelled` | 已取消，不可再操作 |
| `cancelRequested` | `boolean` | 在 `confirmed` 状态下，普通成员申请取消时置 `true` |
| `cancelRejected` | `boolean` | 管理员拒绝取消申请时置 `true`，订单恢复为可正常确认的 `confirmed` |

### 5.3 各角色可操作

| 状态 | 点餐者 | 管理员 |
|------|--------|--------|
| `pending` | 可**取消自己的**待确认订单 | 可批量确认、批量取消、单条取消任意待确认订单 |
| `confirmed` | 可**对自己的**已确认订单发起取消申请 | 可直接取消任意已确认订单；可同意/拒绝取消申请 |
| `cancelRequested` | 看到自己订单显示"申请中"，不可重复申请 | 在取消申请列表中同意或拒绝 |
| `cancelRejected` | 看到自己订单显示"拒绝取消"，点击提示"申请已拒绝，请联系管理员" | 订单恢复为正常 confirmed，可再次取消 |
| `cancelled` | 仅可查看（灰色划掉） | 仅可查看（灰色划掉） |

### 5.4 实时显示规则

今日订单列表（首页 `TodayOrders.vue`）对所有在线成员实时可见，但交互按钮按身份区分：

| 订单状态 | 自己的订单显示 | 他人的订单显示 |
|----------|---------------|---------------|
| `pending` | 红色"取消"按钮 | "⏳" 待确认标记 |
| `confirmed` | "申请取消"按钮（已申请则"申请中"，被拒绝则"拒绝取消"） | "✅" 已确认标记 |
| `cancelled` | 灰色删除线，无操作 | 灰色删除线，无操作 |

### 5.5 实时同步机制

- `watchTodayOrders` 监听 `lunch_orders` 集合中 **今日订单** 的变化
- 所有角色的首页 `onShow` 都会启动该监听；管理员进入管理页 `onShow` 也会启动
- 订单变化时，首页/管理页自动重拉 `getRecentOrders` 或 `loadData()`
- `watchGroupNotice` 监听 `lunch_groups` 的 `notice` 字段，通知变更会实时推送给所有在线成员
- `onHide` 时关闭监听，避免后台耗电

### 5.6 其他规则

- 点餐者提交后**不可自行修改或撤回**，提示"已提交，请联系管理员"
- 点餐者可**取消自己的待确认订单**
- 点餐者可**申请取消自己的已确认订单**，需管理员审批
- 管理员可批量确认 pending 订单
- 管理员可修改/取消任意订单
- 过期待确认订单（`date < today && status === pending`）每天自动取消

## 六、页面设计

### 6.1 首页

```
┌─────────────────────────────┐
│  🍚 我要干饭        张三 👤 │  ← 点击头像/姓名 → 编辑姓名弹窗
│  2026年06月21日              │  ← 年月日
│                              │
│  ┌──────────┐ ┌──────────┐  │
│  │  月点单数 │ │  今日点单数│  │
│  │  56      │ │  4        │  │
│  └──────────┘ └──────────┘  │
│   ↑云端聚合(monthSummary.count)│
│   ↑本地计算(recentOrders过滤， │
│     不含已取消)              │
├──────────────────────────────┤
│  今日点单                     │
│  ┌────────────────────────┐ │
│  │ 张三  红烧肉        ⏳│ │  ← ⏳待确认（橙色）
│  │ 李四  宫保鸡丁      ✅│ │  ← ✅已确认（绿色）
│  │ 王五  鱼香肉丝      ❌│ │  ← ❌已取消（灰色）
│  └────────────────────────┘ │
│  注：列表不显示金额；自己可点  │
│  取消/申请取消，他人仅看状态   │
├──────────────────────────────┤
│  [首页]  [菜单]  [统计]  [管理]│  ← 管理员4个Tab
└──────────────────────────────┘
```

**右上角头像/姓名交互：**
- 显示 `displayName`
- 点击后弹出编辑姓名弹窗
- 保存姓名 → 调用 `updateMemberName`
- 存在虚拟成员时显示"关联已有记录"

**首次入组交互：**
- 打开小程序后，自动调用 `joinGroup` 创建成员记录
- 弹出隐私协议，同意后继续
- 紧接着弹出姓名输入弹窗（可跳过）

### 6.2 菜单页

- 普通用户视角：显示可见菜品（菜名 + 供应商），**不显示价格**
- 管理员视角：在"管理"页"菜单管理"中才显示价格，并可编辑
- 表头供应商/餐品联动筛选
- 已选菜品显示在底部点餐栏
- 切换"为自己点" / "帮[同事]点"
- 长按麦克风按钮语音点餐

### 6.3 统计页 — 仅管理员可见

- 非管理员在 TabBar 中看不到"统计"入口；若通过其他方式进入，页面 `onShow` 会跳转回首页
