> 全局常量速查表见 [30.6-公司午饭点餐小程序方案.md](30.6-公司午饭点餐小程序方案.md)

## 一、需求总览

| 项目 | 说明 |
|------|------|
| 名称 | 我要干饭 |
| Logo | `docs/hp logo.png` |
| 用户 | HP 公司约 20 名同事 |
| 场景 | 每天午饭点餐，管理员确认后下单 |
| 入组 | 无会话先选组 | 首次打开进入选组页，可创建组织、按组名加入或进入已加入组织；进入后首次弹出隐私协议与姓名输入框（可跳过） |
| 数据隔离 | 与账本共用 TCB 环境，所有集合/云函数/存储路径以 `lunch_` 前缀隔离 |
| 运行模式 | 多组织始终开启；`GROUP_ID='lunch_hp'` 只是前端/云函数 `groupId` 的默认回退值，没有 `APP_MODE` 开关 |

### 核心功能

| 模块 | 功能 | 说明 |
|------|------|------|
| **用户进入** | 打开即进 | 自动加入点餐组；首次弹出姓名输入框（可跳过） |

| **统计页** | 筛选详单 | **仅管理员可见**；年月日\|姓名\|餐品\|金额\|供应商 |
| **统计页** | 柱状图下载 | **仅管理员可用**；分月聚合数据可下载 |
| **管理页（pages/data）** | 订单管理 | 待确认列表 + 批量确认；已确认列表按供应商分组 |
| **管理页** | 取消申请 | 查看普通成员对已确认订单的取消申请 |
| **管理页** | 成员管理 | 查看成员列表，编辑任意成员姓名，设置管理员，删除成员 |
| **管理页** | 下载确认单 | 已确认订单下载，可选按供应商分文件或一并下载 |

| **管理页** | 停止接单时间 | 设置每天截止时间、启用/禁用；首页到点后显示本地提示 |
| **管理页** | 数据备份 | 手动/自动备份、恢复、全量导出、清空数据 |
| **权限** | 统计页/管理页仅管理员可见 | 点餐者 TabBar 不显示统计/管理入口 |

## 三、TabBar 配置

**管理员视角：**
```
[首页]    [菜单]    [统计]    [管理]
```

**点餐者视角：**
```
[首页]    [菜单]
```

CustomTabBar 根据 `role` 动态渲染：
- 创建者/管理员：4 个 Tab（首页、菜单、统计、管理）
- 普通点餐者：仅 2 个 Tab（首页、菜单），统计/管理 Tab 不显示
- 统计页和管理页 `onShow` 均有权限守卫，非管理员会跳转回首页

## 四、数据模型

### 4.1 lunch_groups（点餐组）

> 默认 `_id = "lunch_hp"`。随时可在选组页创建新组织，新组 `_id` 由系统生成。

```
_id               // 默认 "lunch_hp"；新建组为 lunch_{ts}_{random}
groupId           // 同 _id
name              // 组名，全局唯一，如"HP午饭"
creatorId         // 创建者 openid
qrcode            // 入口二维码场景值（保留，暂不使用）
createdAt         // 创建时间
menuTimestamp     // 菜单最后更新时间
membersTimestamp  // 成员最后更新时间
ordersTimestamp   // 订单最后更新时间
dataTimestamp     // 月度统计最后重建时间；0 表示需要重建（恢复备份完成后置 0）
orderCutoff       // 每天停止接单时间，默认 "10:00"
cutoffDisabled    // 是否禁用停止接单时间
activeRequests    // 写请求租约 {token: expireAt}，requestGate 维护
restoreJob        // 恢复任务快照（恢复期间存在）
lastRestore       // 最近一次成功恢复记录
```

> 组文档中没有 `notice` / `noticeUpdatedAt`。当前“通知”是前端根据 `orderCutoff` + `cutoffDisabled` 在截止后本地计算并展示的提示，不再写库、没有通知 Tab。

### 4.2 lunch_members（成员）

```
_id
name              // 姓名（用户输入，可为空）
nickName          // 微信昵称（自动获取，name为空时的显示名）
avatar            // 头像 fileID（云存储路径，用户主动选择后上传）
openid            // 微信 openid（虚拟成员为空，登录后补上）
role              // creator / admin / member
isVirtual         // 是否虚拟成员（true=帮人点餐时创建 / false=已登录）
privacyAgreed     // 是否同意隐私协议
joinedAt          // 加入时间
lastOrderedAt     // 最后点餐时间（用于成员排序）
```

**姓名显示规则：**
- `name` 有值 → 显示 `name`
- `name` 为空 → 显示 `nickName`（微信昵称）
- 前端统一用 `displayName = name || nickName`

**虚拟成员规则：**
- 帮人点餐时 [＋新增同事] 创建的成员，`openid` 为空字符串，`isVirtual = true`
- 虚拟成员在成员列表中显示"未登录"标记
- 当前实际提供两个绑定入口：
  - **首页自助关联** — 右上角头像/姓名 → 姓名弹窗 → “关联已有记录”，选择虚拟成员后调用 `linkVirtualMember`
  - **管理页管理员代关联** — 成员管理 → 编辑虚拟成员姓名 → “关联微信账号”，选择已登录微信成员后调用 `adminLinkVirtualMember`
- **未实现**：`joinGroup` 虽然会返回 `virtualMatch`（按姓名精确匹配虚拟成员），但当前前端没有消费该字段，不会在登录时自动弹出“是否关联”确认框。早期文档描述的“入口1 自动匹配”属于历史设计，不是当前行为。

**虚拟成员关联的实际数据方向（容易误解）：**
- 自助关联：把**当前微信成员**的订单 `memberId/memberName` 和个人点餐统计转移到虚拟成员，虚拟成员挂上当前 openid，**删除当前微信成员记录**，最终保留虚拟成员的姓名和历史订单。
- 管理员代关联：把**目标微信成员**的订单和统计转移到虚拟成员，虚拟成员挂上目标 openid，删除目标微信成员记录。
- 两种方式最终都保留虚拟成员 `_id`，因此历史订单不需要改菜单/统计外部引用。

**头像处理：**
- 微信已废弃 `wx.getUserProfile`，无法自动获取微信头像
- 使用 `<button open-type="chooseAvatar" @chooseavatar="onChooseAvatar">` 方式
- 用户主动选择头像后，保存姓名时上传到云存储，路径为 `lunch/avatar_{memberId}_{timestamp}.jpg`（不是 `lunch/avatar/` 子目录），随后调用 `updateMemberProfile` 写入 `member.avatar`
- 未设置头像时，显示姓名首字的彩色圆形占位符

**菜单照片：**
- `lunch_menu.photo` 字段和 `addMenuItem/updateMenuItem` 的 `photo` 参数存在，但当前前端管理页没有“上传照片”入口，也没有 `wx.chooseMedia` 上传/删除逻辑。
- 因此当前实际使用中 `photo` 基本为空；文档不再把照片上传描述为已实现功能。若后续启用，需补齐上传、展示与删除文件三处代码。

### 4.3 lunch_menu（菜单）

```
_id
name              // 餐品名
supplier          // 供应商
price             // 价格（数字）
photo             // 照片 fileID（可选，为空则不显示）
sortNo            // 序号（排序用，整数，间距10便于插入）
visible           // 是否可见（true=可见 / false=隐藏）
orderCount        // 累计点餐次数（用于动态排序）
lastOrderedAt     // 最近点餐时间（用于动态排序）
createdAt         // 创建时间
```

**visible 字段规则：**
- `true`：普通成员菜单页可见可点
- `false`：普通成员菜单页完全不显示；管理页“菜单管理”仍列出，可恢复可见
- 切换可见性时，云函数会把该项 `sortNo` 排到对应分组（可见组/隐藏组）末尾，不会插回原位置
- 当前没有“上移/下移”接口；菜品的顺序主要由 `visible` 分组、`lastOrderedAt` LRU 和 `orderCount` 决定，`sortNo` 只作兜底

### 4.4 lunch_orders（订单）

```
_id
groupId           // 所属组
memberId          // 下单人ID
memberName        // 下单人姓名（冗余快照）
menuId            // 菜品ID
menuName          // 菜品名（冗余快照）
supplier          // 供应商（冗余快照）
price             // 金额（保留两位小数）
note              // 备注（≤500 字）
date              // 日期 "2026-06-16"
status            // pending / confirmed / cancelled
cancelRequested   // 是否已申请取消（仅 confirmed 状态有效）
cancelRejected    // 取消申请是否被拒绝
createdBy         // 提交者 openid（帮人点餐时为操作人）
createdAt         // 下单时间
updatedAt         // 最后更新时间
```

> 当前代码没有写入 `confirmedAt` 字段；确认只更新 `status` 和 `updatedAt`。删除成员/菜品不会级联删除订单，订单仍依靠 `memberName`/`menuName`/`supplier`/`price` 快照展示与统计。

### 4.5 lunch_monthly_stats（月度聚合统计）

```
_id               // {groupId}_{year}_{month}，确定性ID
groupId           // 所属组
year              // 年份
month             // 月份
totalAmount       // 月总金额
orderCount        // 订单数
orderByMember     // [{ memberId, memberName, amount, count }, ...]
orderBySupplier   // [{ supplier, amount, count }, ...]
orderByMemberMap  // { "张三": 560, "李四": 420, ... }
orderBySupplierMap// { "老王": 880, "小李": 640, ... }
deleted           // true=该月已无已确认订单，保留删除标记供前端移除缓存
createdAt         // 创建/重建时间
updatedAt         // 更新时间
```

> 重建时 `_id` 固定为 `{groupId}_{year}_{month}`。增量请求通过 `updatedAt > since` 找变化月份；某月最后一条确认订单被取消后，会写入 `deleted: true` 的空记录而不是直接删除，前端据此从缓存中移除该月。

### 4.6 lunch_user_menu_stats（个人点餐统计）

```
_id               // {groupId}_{memberId}_{menuId}，确定性ID
groupId           // 所属组
memberId          // 成员ID
menuId            // 菜品ID
count             // 累计点过次数
lastAt            // 最近点餐时间
```

### 4.7 辅助集合（维护时容易忽略）

| 集合 | 作用 | 关键点 |
|------|------|--------|
| `lunch_order_keys` | 下单幂等锁 | `_id = order_{sha256(groupId,date,memberId,menuId)}`；事务中检查 `orderId` 是否仍为 pending |
| `lunch_audit_logs` | 操作审计 | 成员/菜单/导入写操作记录 old/new 值；`expireAt` 约 2 年，审计失败不阻断业务 |
| `lunch_voice_usage` | 语音日配额 | `_id = {openid}_{YYYY-MM-DD}`，`count` 上限 30；不随业务备份恢复 |

## 五、订单状态机

### 5.1 状态流转

```
                    点餐者提交
  （未下单） ──────────────▶ pending（待确认）
                                 │
                    管理员确认    │    管理员取消 / 自动过期 / 自己取消
                 ┌───────────────┘──────────────┐
                 ▼                              ▼
          confirmed（已确认）           cancelled（已取消）
                 │
     普通成员申请取消
                 │
                 ▼
     cancelRequested=true（等待管理员处理）
                 │
        管理员同意取消 ───────▶ cancelled
        管理员拒绝取消 ───────▶ cancelRejected=true，恢复 confirmed
```

### 5.2 状态字段定义

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | `pending` | 待确认，刚提交，管理员未确认 |
| `status` | `confirmed` | 已确认，管理员已确认 |
| `status` | `cancelled` | 已取消，不可再操作 |
| `cancelRequested` | `boolean` | 在 `confirmed` 状态下，普通成员申请取消时置 `true` |
| `cancelRejected` | `boolean` | 管理员拒绝取消申请时置 `true`，订单恢复为可正常确认的 `confirmed` |

### 5.3 各角色可操作

| 状态 | 点餐者 | 管理员 |
|------|--------|--------|
| `pending` | 可**取消自己的**待确认订单 | 可批量确认、批量取消、单条取消任意待确认订单 |
| `confirmed` | 可**对自己的**已确认订单发起取消申请 | 可直接取消任意已确认订单；可同意/拒绝取消申请 |
| `cancelRequested` | 看到自己订单显示"申请中"，不可重复申请 | 在取消申请列表中同意或拒绝 |
| `cancelRejected` | 看到自己订单显示"拒绝取消"，点击提示"申请已拒绝，请联系管理员" | 订单恢复为正常 confirmed，可再次取消 |
| `cancelled` | 仅可查看（灰色划掉） | 仅可查看（灰色划掉） |

### 5.4 实时显示规则

今日订单列表（首页 `TodayOrders.vue`）对所有在线成员实时可见，但交互按钮按身份区分：

| 订单状态 | 自己的订单显示 | 他人的订单显示 |
|----------|---------------|---------------|
| `pending` | 红色"取消"按钮 | "⏳" 待确认标记 |
| `confirmed` | "申请取消"按钮（已申请则"申请中"，被拒绝则"拒绝取消"） | "✅" 已确认标记 |
| `cancelled` | 灰色删除线，无操作 | 灰色删除线，无操作 |

### 5.5 实时同步机制

- `watchTodayOrders` 监听 `lunch_orders` 集合中 **今日订单**（`groupId + date=today`）的变化
- 所有角色的首页 `onShow` 都会启动该监听；管理员进入管理页 `onShow` 也会启动
- 首页收到变更后**本地增量 patch** `store.recentOrders`，并调用一次 `getMonthSummary` 刷新月汇总
- 管理页收到变更后不做本地 patch，而是经 400ms 防抖后只重拉 `getRecentOrders`（`loadOrdersOnly`）
- 当前**没有** `watchGroupNotice`，也不监听 `lunch_groups`；不存在组通知字段
- `onHide` 时关闭监听；watch 断连按 30s→1min→2min→5min 指数退避重连，首页断连时兜底 `fetchRecentOrders`
- 首页 onShow 另有 10 秒节流的 `checkDataFreshness`（`lunch_menu.getDataTimestamps`）作为 watch 兜底；菜单/成员时间戳变化会在该函数内直接重拉并同步本人角色

### 5.6 其他规则

- 点餐者提交后**不可自行修改或撤回**，提示"已提交，请联系管理员"
- 点餐者可**取消自己的待确认订单**
- 点餐者可**申请取消自己的已确认订单**，需管理员审批
- 管理员可批量确认 pending 订单
- 管理员可修改/取消任意订单
- 过期待确认订单（`date < today && status === pending`）在 `getInitData` / `getRecentOrders` / 自动扫描时取消；云函数按组织做 60 秒实例级节流
- **停止接单时间**：默认 `10:00`，管理员可修改或禁用。普通成员在截止后提交会收到 403；管理员/创建者不受限制。首页在截止后到当日 24:00 显示“每天HH:MM停止接单，有需要请电话联系”的本地提示，不经过云函数通知

**右上角头像/姓名交互：**
- 显示 `displayName`
- 点击后弹出编辑姓名弹窗
- 保存姓名 → 调用 `updateMemberName`
- 存在虚拟成员时显示"关联已有记录"

**首次入组交互：**
- 无本地 `lunch_session` 时，首页 onShow 会 `reLaunch` 到 `pages/group-select`；用户创建组织、按组名加入或进入已加入组织
- 进入组织的真实链路是 `initGroup → joinGroup → 首页 freshness`；`joinGroup` 负责创建/取回 member，通常**不会**再调用 `getInitData`
- 只有 store 里没有 member（异常会话、恢复后等）时，首页 `initApp` 才调用 `getInitData`；该接口内部会按 openid 内联查找/创建成员（不会自动创建组织；组织不存在时 `initGroup` 返回 404）
- 若 `privacyAgreed=false` → 弹出隐私协议，同意后继续
- 若是新成员且 `name` 为空 → 弹出姓名输入弹窗（可跳过；跳过会写入“用户{时间戳}”）

### 6.2 菜单页

- 普通用户视角：显示可见菜品（菜名 + 供应商），**不显示价格**
- 管理员视角：在"管理"页"菜单管理"中才显示价格，并可编辑
- 表头供应商/餐品联动筛选
- 已选菜品显示在底部点餐栏
- 切换"为自己点" / "帮[同事]点"
- 点击麦克风按钮开始录音，再次点击结束（不是长按）

### 6.3 统计页 — 仅管理员可见

- 非管理员在 TabBar 中看不到"统计"入口；若通过其他方式进入，页面 `onShow` 会跳转回首页
- 汇总卡片：总金额、订单数
- 月度趋势柱状图（带金额标签）
- 供应商占比饼图（带金额）
- 筛选详单列表（含金额、供应商）
- 右下角 FAB 筛选按钮：年份 + 月份 + 点餐人 + 供应商
- 柱状图数据下载

### 6.4 管理页（pages/data）— 仅管理员可见

- 停止接单时间：修改时间、启用/禁用
- 待确认订单 + 批量确认 / 批量取消；可展开历史待确认
- 已确认订单按供应商分组 + 批量取消 + 下载；可展开历史已确认
- 取消申请列表（同意复用 `cancelOrder`，拒绝调用 `rejectCancelRequest`）
- 成员管理（改名、设/撤管理员、删除、虚拟成员关联微信）
- 菜单管理（增删改、单项显隐、按供应商批量显隐）
- 导入导出（订单/菜单/成员，CSV/XLSX）
- 订单关联修复（`rebuildOrderRelations`）
- 数据备份 / 恢复
- 危险操作：清空数据、删除组织（仅创建者）
