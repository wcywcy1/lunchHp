## 一、概述

「我要干饭」是面向 HP 公司约 20 名同事的午饭点餐小程序，基于 **uni-app + Vue3 + TypeScript + 微信云开发** 实现。

- **应用名**：我要干饭（导航栏标题）
- **当前模式**：hp_lunch 专用（单租户，`GROUP_ID = 'lunch_hp'` 写死）
- **云环境**：`cloud1-d0g9zww8h390b6f41`
- **数据隔离**：所有集合/云函数/存储路径以 `lunch_` 前缀隔离，可与账本共用同一云环境

核心流程：成员在菜单页点餐 → 管理员在管理页批量确认 → 生成确认单下载 → 月度统计自动聚合。

## 二、程序模式与切换

### 2.1 两种模式

| 模式 | `GROUP_ID` 取值 | 适用场景 |
|------|-----------------|----------|
| **hp_lunch 专用程序**（默认） | `'lunch_hp'` | 单一组织，所有人加入同一组 |
| **通用程序（多组织）** | 运行时切换为任意组ID | 一套代码服务多个组织，数据按 `groupId` 隔离 |

### 2.2 一键切换（已实现）

**支持运行时一键切换**，无需改代码、无需重新部署云函数。切换入口位于：管理页 → 组织切换区块（仅 `creator` 可见）。

**实现原理：**
- 前端 [src/constants/appConfig.ts](../src/constants/appConfig.ts) 保留 `GROUP_ID = 'lunch_hp'` 作为默认回退值
- 当前激活组ID持久化在 localStorage 键 `lunch_active_group_id`（[src/services/store.ts](../src/services/store.ts) 的 `getActiveGroupId` / `setActiveGroupId`）
- 所有云函数调用自动注入当前 groupId（[src/services/repositories/baseRepository.ts](../src/services/repositories/baseRepository.ts)）
- 3 个云函数 main 入口从 `event.groupId` 动态读取，回退默认值（`lunch_menu`、`lunch_order`、`lunch_backup`）

### 2.3 切换操作步骤

1. 以 `creator` 身份进入「管理」页
2. 滚动到「数据备份」下方的「组织切换」区块
3. 区块顶部显示「当前组织：lunch_hp」
4. 在「目标组ID」输入框填入目标组ID（如 `lunch_companyB`），或点击「填入默认」快速填入 `lunch_hp`
5. 点击「一键切换」
6. 弹窗确认后，系统自动执行：
   - 停止实时监听
   - 清空所有本地缓存和会话
   - 写入新组ID到本地存储
   - 重置初始化缓存，重新调用 `initGroup`（目标组不存在则自动创建）
   - 调用 `joinGroup` 加入目标组
   - 跳转回首页，加载目标组织数据

### 2.4 切换后的影响

| 项目 | 影响 |
|------|------|
| 本地缓存 | 全部清空（订单、菜单、成员、统计、会话） |
| 当前用户角色 | 在目标组中重新加入，默认为 `member`；若已是该组 creator 则保留 |
| 历史数据 | 不受影响，原组织数据保留在云端，按 `groupId` 隔离 |
| 其他用户 | 不受影响，仍在各自激活的组织中 |
| 云函数 | 无需重新部署，自动按传入的 `groupId` 处理 |

### 2.5 注意事项

- **仅 creator 可切换**：普通成员和管理员看不到切换入口
- **切换是本机行为**：只影响当前设备的当前微信账号，不改变其他用户
- **组ID命名规范**：建议以 `lunch_` 开头（如 `lunch_hp`、`lunch_companyB`），与集合前缀保持一致
- **首次进入新组**：会触发 `initGroup` 自动创建组记录，并弹出欢迎姓名输入框
- **回退到 hp_lunch**：在目标组ID输入 `lunch_hp` 切换即可

### 2.6 部署层面的模式切换（可选）

除运行时一键切换外，仍支持部署层面切换默认组织：修改 [src/constants/appConfig.ts](../src/constants/appConfig.ts) 的 `GROUP_ID` 默认值，重新构建发版。这会影响所有新用户的初始组织。

## 三、角色与权限

系统内置三种角色，定义于 [src/constants/orderStatus.ts](../src/constants/orderStatus.ts)：

| 角色 | 标识 | 获取方式 | 权限 |
|------|------|----------|------|
| 创建者 | `creator` | 首个加入组的成员 | 全部权限，含设/撤管理员、删除数据 |
| 管理员 | `admin` | 由创建者任命 | 菜单管理、订单确认/取消、统计、管理页 |
| 普通成员 | `member` | 默认 | 点餐、查看首页、编辑自己姓名 |

**底部 TabBar 可见性**（见 [CustomTabBar.vue](../src/components/CustomTabBar/CustomTabBar.vue)）：

- `creator` / `admin`：首页、菜单、统计、管理（4 个 Tab）
- `member`：首页、菜单（2 个 Tab，统计/管理页强制跳转回首页）

## 五、终端用户操作指南

### 5.1 首次进入

1. **隐私协议**：首次打开弹出隐私协议弹窗，点击「同意并继续」进入；点击「不同意」则不继续。
2. **欢迎弹窗**：输入姓名（选填），不填则使用微信昵称。点击「确认」保存，或「跳过」稍后设置。
3. 系统自动调用 `initGroup` 初始化点餐组（若不存在则创建）。

### 5.2 首页

**界面元素**（[pages/home](../src/pages/home/index.vue)）：

- 顶部：标题「🍚 我要干饭」+ 当天日期；右侧头像（姓名首字）+ 显示名
- 月度卡片：月合计金额（橙色）、今日金额（蓝色）
- 今日点单列表：按状态分组显示
  - 已确认（绿色标签，✅）
  - 待确认（橙色标签，⏳）
  - 已取消（灰色，删除线）
- 通知滚动条：管理员发送的通知以红色跑马灯形式展示

**操作**：

| 操作 | 说明 |
|------|------|
| 点击右上角头像/姓名 | 弹出姓名编辑框，可修改自己的姓名 |
| 下拉刷新 | 重新拉取今日数据 |
| 取消自己的待确认订单 | 列表中自己的待确认订单显示「取消」按钮，点击直接取消 |
| 申请取消自己的已确认订单 | 已确认订单显示「申请取消」按钮，提交后进入管理员审批流程；审批中显示「申请中」；被拒绝显示「拒绝取消」 |

**虚拟成员绑定**：若姓名与某虚拟成员（帮人点餐时创建的未登录成员）同名，编辑姓名时会提示「与微信账号合帐」，确认后该虚拟成员绑定到当前微信。

### 5.3 菜单页（点餐）

**界面元素**（[pages/menu](../src/pages/menu/index.vue)）：

- 顶部 tab 栏：`全部 | 常点 | 供应商...`（[MenuFilter.vue](../src/components/menu/MenuFilter.vue)）
  - **全部**：所有可见菜品，按最近点餐时间（LRU）→ 频率 → sortNo 排序
  - **常点**：个人常点优先，不足 9 个用大众常点补齐，平铺不分组，最多显示 9 个
  - **供应商 tab**：按供应商分组，tab 顺序按该供应商最近被点餐时间降序
- 菜单列表：仅显示「可见」状态的菜品（序号、供应商、餐品、价格）
- 底部点餐栏：已选菜品信息 + 「为自己点 / 帮人点」切换 + 提交/语音按钮

**「常点」tab 规则**（[useMenuFilter.ts](../src/hooks/useMenuFilter.ts)）：

- **个人常点**：当前用户点过的菜（`userCount > 0`），按最近点餐时间降序（LRU，不看频率，新菜点一次即进）
- **大众常点补齐**：个人常点不足 9 个时，用其他同事点过的菜（`orderCount > 0`）按最近点餐时间降序补齐，没被任何人点过的菜不补
- **上限**：最多 9 个（个人常点在前，逐步取代大众常点）
- **默认 tab**：进入菜单页时若有常点记录，默认选中「常点」tab
- **帮他人点餐**：切换到「帮人点」并选择同事后，「常点」tab 自动按被帮人的个人统计排（拉取被帮人的 `lunch_user_menu_stats`）

**点餐流程**：

1. 通过 tab 切换、筛选或语音找到目标菜品，点击选中（底部显示菜品名+价格）
2. 选择「为自己点」或「帮人点」
   - 帮人点：弹出成员选择器，选择同事；或点击「＋新增同事」创建虚拟成员
3. 点击「提交点餐」提交，订单状态为「待确认」

**语音搜索**：

- 未选菜品时，底部按钮显示「点击说话」
- 点击开始录音，再次点击结束；识别中显示「识别中...」
- 识别结果优先反向匹配菜单名（菜名出现在文本中即命中），否则用关键词模糊匹配
- 录音过程显示底部波形面板

## 六、管理员操作指南

> 以下功能仅 `creator` / `admin` 可见。普通成员访问统计/管理页会被强制跳转回首页。

### 6.1 统计页

**界面元素**（[pages/stats](../src/pages/stats/index.vue)）：

- 汇总卡片：总金额、总单数
- 柱状图：按月度展示，点击可下载该月数据
- 饼图：按供应商/成员占比
- 明细列表：分页加载历史订单
- 右下角浮动「筛选」按钮（有激活筛选时变橙色）

**操作**：

| 操作 | 说明 |
|------|------|
| 点击筛选浮按 | 打开筛选面板（年份、月份、成员、供应商多选） |
| 应用/重置筛选 | 重新加载统计数据 |
| 点击柱状图 | 下载对应月度数据 |
| 下拉刷新 | 重新加载统计（30 秒内不重复加载） |

### 6.2 管理页

管理页是一个长滚动页面，从上到下依次为以下模块（[pages/data](../src/pages/data/index.vue)）：

#### 6.2.1 发送通知

- 输入通知内容，点击「发送」实时推送给所有在线成员
- 通知当天 0 点自动过期
- 可点击「清除通知」立即移除当前通知

#### 6.2.2 待确认订单

- 列出当日待确认订单，支持单选/全选
- 「批量确认」：选中订单状态变为已确认
- 「批量取消」：选中订单状态变为已取消
- 可展开历史待确认订单，分页加载

#### 6.2.3 取消申请列表

- 展示已确认订单的取消申请
- 「批准」：订单变为已取消
- 「拒绝」：订单保持已确认，申请人首页显示「拒绝取消」

#### 6.2.4 已确认订单

- 列出当日已确认订单，支持单选/全选
- 「批量取消」：选中订单变为已取消
- 「下载」：弹出下载对话框，可选「按供应商分别下载」或「一并下载」生成确认单
- 可展开历史已确认订单，分页加载

#### 6.2.5 成员管理

- 查看所有成员列表
- 「改名」：修改成员姓名（虚拟成员可「与微信账号合帐」）
- 「设为管理员 / 撤销管理员」：仅 creator 可操作
- 「删除成员」：移除成员（creator 不可删除自己）

#### 6.2.6 菜单管理

- 查看全部菜品（含隐藏项）
- 「添加菜品」：填写供应商、餐品名、价格
- 「编辑 / 删除」菜品
- 「上移 / 下移」调整排序
- 「切换可见/隐藏」：隐藏后普通成员点餐时看不到
- 「按供应商批量显隐」：整组切换

#### 6.2.7 导入导出

- **导出**：可选导出订单/菜单/成员数据
- **导入**：可选导入订单/菜单/成员，支持 `csv`、`xlsx` 格式

#### 6.2.8 数据备份

- 「立即备份」：创建手动备份
- 「恢复备份」：三步流程
  1. **选择备份**：列表展示自动备份（🟢）和手动备份（🔵），含时间、订单/菜品/成员数量
  2. **备份预览**：查看类型、时间、数量、数据范围、备注
  3. **确认恢复**：恢复前自动创建一次手动备份以防误操作

#### 6.2.9 组织切换（仅 creator 可见）

- 显示当前组织ID
- 输入目标组ID，点击「一键切换」
- 详见 [第二章 2.3 节](#23-切换操作步骤)

#### 6.2.10 危险操作

- 「删除数据」：清空当前组数据（高危，需谨慎）
- 「删除账号」：**当前不可用**，提示「当前组织ID为系统预设」（因 `GROUP_ID` 写死）

## 七、部署指南

### 7.1 前置条件

- 微信开发者工具
- 已注册微信小程序，获取 AppID
- 已开通微信云开发环境

### 7.2 首次部署步骤

1. **修改 AppID**：编辑 [src/manifest.json](../src/manifest.json)，填入小程序 AppID
2. **配置云环境**：确认 [src/constants/appConfig.ts](../src/constants/appConfig.ts) 中 `CLOUD_ENV` 为目标云环境 ID
3. **安装依赖**：
   ```bash
   npm install
   ```
4. **部署云函数**：在微信开发者工具中，右键 `wxcloud/functions/` 下三个云函数（`lunch_menu`、`lunch_order`、`lunch_backup`），选择「上传并部署：云端安装依赖」
5. **初始化数据**：首次打开小程序时自动调用 `initGroup` 创建 `lunch_groups` 记录，无需手动建表
6. **本地预览**：
   ```bash
   npm run dev:mp-weixin
   ```
   在微信开发者工具打开 `dist/dev/mp-weixin` 目录预览
7. **生产构建**：
   ```bash
   npm run build:mp-weixin
   ```
   通过微信开发者工具上传发版

### 7.3 云环境切换（测试 ↔ 生产）

只需修改 [src/constants/appConfig.ts](../src/constants/appConfig.ts) 的 `CLOUD_ENV` 一个配置项，无需改代码：

- 测试阶段：填独立测试环境 ID
- 生产阶段：填账本共用环境 ID（通过 `lunch_` 前缀隔离）

### 7.4 切换组织 / 切换模式

参见 [第二章](#二程序模式与切换)。

### 8.5 缓存策略

本地缓存键与 TTL 定义于 [src/constants/cacheConfig.ts](../src/constants/cacheConfig.ts)：

| 缓存 | TTL |
|------|-----|
| 成员列表 | 30 分钟 |
| 菜单 | 30 分钟 |
| 近期订单 | 5 分钟 |
| 月度汇总 | 5 分钟 |

## 九、常见问题

**Q1：普通成员看不到统计和管理页？**
A：正常。`member` 角色只有首页和菜单两个 Tab，访问统计/管理页会被强制跳转回首页。需 creator 任命为 admin。

**Q2：如何成为管理员？**
A：只有 creator 能任命。creator 在管理页 → 成员管理 → 点击成员「设为管理员」。

**Q3：已确认订单还能取消吗？**
A：可以。成员在首页对自己已确认订单点「申请取消」，管理员在管理页「取消申请列表」中审批。审批通过才真正取消。

**Q4：帮没注册的同事点餐怎么办？**
A：菜单页选「帮人点」→「＋新增同事」→ 输入姓名创建虚拟成员，即可代点。该同事后续登录时可「与微信账号合帐」绑定。

**Q5：通知发错了怎么改？**
A：管理页 → 发送通知 →「清除通知」移除当前通知，再重新发送。通知当天 0 点自动过期。

**Q6：误删数据能恢复吗？**
A：可以。管理页 → 数据备份 → 恢复备份，选择误操作前的自动/手动备份恢复。恢复前系统会自动创建一次手动备份。

**Q7：能不能一套代码给多个公司用？**
A：可以。creator 在管理页 → 组织切换区块，输入目标组ID点击「一键切换」即可进入新组织。数据按 `groupId` 隔离，互不影响。详见 [第二章](#二程序模式与切换)。

**Q8：切换云环境会丢数据吗？**
A：不会。切换云环境只是连接到不同环境，原环境数据保留。但注意不同环境的数据不互通。
