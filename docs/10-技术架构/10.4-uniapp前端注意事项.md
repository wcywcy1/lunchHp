# uni-app 前端开发注意事项

> **修改涉及 input 绑定、组件通信、小程序特有 API 的代码前，必须对照此文件。**

## 1. input 绑定：必须用 v-model，禁止 :value + @input

### 问题描述

在 uni-app 微信小程序中，`<input>` 使用 `:value` + `@input` 的方式绑定数据**不可靠**：

```vue
<!-- ❌ 错误：小程序中输入值会被重置 -->
<input :value="propName" @input="emit('update:propName', $event.detail.value)" />

<!-- ✅ 正确：用 v-model 绑定本地 ref -->
<input v-model="localName" />
```

### 根因

uni-app 小程序端对 `:value` 单向绑定的处理与 Web 端不同：
1. 用户输入触发 `@input` → emit 更新父组件的 prop
2. prop 变化 → `:value` 重新赋值
3. 小程序渲染层在赋值瞬间**重置输入框光标和内容**，导致输入丢失或闪烁

Web 端无此问题（Vue 的 DOM diff 会跳过未变化的 value），但小程序端每次 `:value` 赋值都会触发原生 input 的值重设。

### 正确做法

**在组件内部用 `v-model` 绑定本地 ref，通过事件将值传出：**

```vue
<template>
  <input v-model="localName" placeholder="输入姓名" />
  <view @tap="$emit('confirm', localName)">确认</view>
</template>

<script setup lang="ts">
import { ref, watch } from 'vue'

const props = defineProps<{ show: boolean }>()
const emit = defineEmits<{ (e: 'confirm', name: string): void }>()

const localName = ref('')

watch(() => props.show, (val) => {
  if (!val) localName.value = ''
})
</script>
```

## 2. 组件间 input 值传递模式

### 推荐模式：本地 ref + 事件传值

```
子组件：v-model → 本地 ref → emit('confirm', value) → 父组件处理
```

**不要**用 prop 双向绑定（`update:propName`）来传递 input 的值，因为：
- prop 变化会触发 `:value` 重赋值（回到第 1 条问题）
- 多了一层不必要的响应式链路

### 对比

| 模式 | 适用场景 | 小程序可靠性 |
|------|---------|-------------|
| `v-model="localRef"` | 组件内部 input | ✅ 可靠 |
| `:value` + `@input` + emit update | 跨组件双向绑定 input 值 | ❌ 不可靠 |
| `v-model` + emit 事件传值 | 子组件输入→父组件提交 | ✅ 可靠 |
