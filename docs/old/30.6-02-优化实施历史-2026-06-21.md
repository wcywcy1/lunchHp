### 13.2 P0 优化（必做，高收益低成本）

#### O1. 首页 onShow 合并时间戳查询 → 统一 getAllTimestamps（已实施，2026-06-21）

**问题核对**（已确认）：
- `useHome.onShow`（useHome.ts:145）并行调用 `fetchNotice()` + `checkFreshness()`
- `fetchNotice`（useHome.ts:148-162）→ `menuAction('getDataTimestamps')` → 调用 lunch_menu 云函数
- `checkFreshness`（useHome.ts:203-217）→ `orderAction('getRecentTimestamp')` → 调用 lunch_order 云函数
- 两个 action 各启动 1 次云函数，但服务端返回数据有重叠（都读 lunch_groups 文档）

**更优解**：
v2.0 建议两个方案（走 getInitData 或在 getDataTimestamps 加 recentTimestamp）。**更优解是新增统一 action**：

```javascript
// lunch_order/index.js 新增
async function getAllTimestamps(event, openid) {
    const { data } = await db.collection(COL.GROUPS).doc(GROUP_ID).get().catch(() => ({ data: {} }))
    return {
        code: 0,
        data: {
            recentTimestamp: data.ordersTimestamp || null,
            menuTimestamp: data.menuTimestamp || null,
            membersTimestamp: data.membersTimestamp || null,
            dataTimestamp: data.dataTimestamp || null,
            notice: data.notice || '',
            noticeUpdatedAt: data.noticeUpdatedAt || null,
        }
    }
}
```

前端 onShow 改为单次调用，按需拉取变化的数据：

```typescript
async function onShowCheck() {
    const res = await orderAction('getAllTimestamps')
    const { recentTimestamp, menuTimestamp, membersTimestamp, notice, noticeUpdatedAt } = res.result.data
    applyNotice(notice, noticeUpdatedAt)
    if (recentTimestamp !== store.recentTimestamp) await fetchRecentOrders(recentTimestamp)
    if (menuTimestamp !== store.menuTimestamp) setStore({ menuTimestamp })
    if (membersTimestamp !== store.membersTimestamp) setStore({ membersTimestamp })
}
```

**为什么比 v2.0 方案更优**：
- v2.0 方案 A（用 getInitData）：每次 onShow 都返回完整 recentOrders/menu/members，数据量大
- v2.0 方案 B（getDataTimestamps 加 recentTimestamp）：仍走 lunch_menu，但 recentTimestamp 属于订单域，职责不清
- **本方案**：1 次轻量调用（只返回 6 个字段），前端按需拉取变化的数据，职责清晰

**前后对比**：

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| onShow 云函数调用次数 | 2 次（lunch_menu + lunch_order） | 1 次（lunch_order） |
| 冷启动概率 | 2 倍 | 1 倍 |
| 数据传输量 | 2 个响应体 | 1 个轻量响应体（~200B） |
| 10 人日均切页 20 次 | 400 次云函数/天 | 200 次云函数/天 |

**落地步骤**：
1. lunch_order/index.js 注册 `getAllTimestamps` action
2. useHome.ts 新增 `onShowCheck()`，替换 `fetchNotice + checkFreshness`
3. useDataManage.ts 的 `loadData()` 也改用 `getAllTimestamps`（替代 getDataTimestamps）
4. 保留 `getDataTimestamps` / `getRecentTimestamp` 作为兼容（或下个版本删除）

**验收标准**：
- [x] 首页 onShow 仅触发 1 次云函数调用（开发者工具 Network 面板验证）
- [x] 通知、订单、菜单时间戳均能正确感知变化
- [x] 切换组后 onShow 仍能正常工作

```typescript
// useRealtimeWatch.ts 增强
function watchTodayOrders(onChange: (snapshot: any) => void) {
    closeOrderWatcher()
    const db = wx.cloud.database()
    orderWatcher = db.collection(COLLECTIONS.ORDERS)
        .where({ groupId: GROUP_ID, date: getToday() })
        .watch({
            onChange: (snapshot) => {
                if (snapshot.type === 'init') {
                    onChange({ type: 'init', docs: snapshot.docs })
                    return
                }
                onChange({ type: 'changes', changes: snapshot.docChanges || [] })
            },
            onError: (err) => { /* 见 O8 */ }
        })
}

// useHome.ts 调用方
realtime.watchTodayOrders((payload) => {
    if (payload.type === 'init') return // 已有 loadInitData
    const orders = [...store.recentOrders]
    for (const c of payload.changes) {
        const idx = orders.findIndex(o => o._id === c.doc._id)
        const t = c.queueType || c.dataType
        if (t === 'add' && idx < 0) orders.unshift(c.doc)
        else if (t === 'update' && idx >= 0) orders[idx] = c.doc
        else if (t === 'remove' && idx >= 0) orders.splice(idx, 1)
    }
    setStore({ recentOrders: orders })
    setCache(CACHE_KEYS.RECENT_ORDERS, orders)
})
```

#### O8. watch onError 降级 + 退避重建（已实施，2026-06-21）

- 断连后到下次 onShow 之间，用户看到过期数据

**更优解**：保留 v2.0 方案，补充指数退避：

```typescript
function watchTodayOrders(onChange, onFallback) {
    let retryCount = 0
    let retryTimer: any = null

    const start = () => {
        orderWatcher = db.collection(COLLECTIONS.ORDERS)
            .where({ groupId: GROUP_ID, date: getToday() })
            .watch({
                onChange,
                onError: (err) => {
                    console.error('[watch] error:', err)
                    orderWatcher = null
                    onFallback?.() // 立即兜底拉取
                    // 指数退避：30s, 60s, 120s, 最大 5 分钟
                    const delay = Math.min(30000 * Math.pow(2, retryCount++), 300000)
                    retryTimer = setTimeout(start, delay)
                },
            })
    }
    start()

    return {
        close: () => {
            if (retryTimer) clearTimeout(retryTimer)
            orderWatcher?.close()
            orderWatcher = null
        }
    }
}
```

#### O19. setCache 同步写阻塞（新增，已实施，2026-06-21）

**问题核对**：

**更优解**：防抖 + 批量写：

```typescript
const pendingWrites = new Map<string, any>()
let writeTimer: any = null

export function setCache(key: string, data: any) {
    pendingWrites.set(key, data)
    if (writeTimer) clearTimeout(writeTimer)
    writeTimer = setTimeout(flushWrites, 500)
}

function flushWrites() {
    for (const [key, data] of pendingWrites) {
        uni.setStorageSync(key, JSON.stringify({ data, ts: Date.now() }))
    }
    pendingWrites.clear()
    writeTimer = null
}
```
