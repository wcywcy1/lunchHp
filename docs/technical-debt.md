# 技术债与重构评估

## `lunch_order` 云函数精简评估

记录日期：2026-09-16

状态：暂缓执行，后续再议。

### 现状

- `wxcloud/functions/lunch_order/index.js` 约 1996 行，包含约 43 个内部函数。
- 同时负责订单查询和状态流转、月度统计、CSV/XLSX 导入、数据导出、成员关系修复、缓存时间戳和接口分发。
- 当前 26 项回归测试全部通过。
- 覆盖率评估结果：该文件行覆盖率约 44.44%，函数覆盖率约 46.60%。
- 导入导出、搜索、关系修复和部分状态入口的测试覆盖不足，不适合立即进行全面重构。

### 候选优化

1. 合并时间戳更新函数。
   - 收益：减少约 40–60 行重复代码，统一组织记录不存在时的创建逻辑。
   - 风险：低。

2. 将 CSV/XLSX 解析及导入逻辑移入独立的 `importers.js`。
   - 收益：主文件预计减少约 400–500 行，导入逻辑更容易单独测试。
   - 风险：中。
   - 前置条件：补齐 CSV 引号与换行、XLSX 三种导入类型、追加和覆盖导入测试。

3. 将统计查询及重建逻辑移入独立的 `statistics.js`。
   - 收益：主文件预计减少约 200 行，统计职责更清楚。
   - 风险：中。
   - 前置条件：补齐全量、增量、空月份删除标记和多月份重建测试。

4. 使用统一中间件处理角色和目标数据权限。
   - 收益：减少接口内重复校验。
   - 风险：高，容易改变现有权限边界和错误返回顺序。
   - 结论：暂不执行。

5. 删除前端当前未调用的读取接口。
   - 涉及：`getRecentTimestamp`、`getRecentMenu`、`getRecentMembers`。
   - 风险：中高，旧版本客户端可能仍在调用。
   - 结论：没有客户端版本和调用数据前不删除。

### 建议执行顺序

1. 先增加导入和统计的特征测试。
2. 合并时间戳更新函数。
3. 只拆分导入模块，保持接口名、返回结构和 `requestGate` 规则不变。
4. 验证稳定后再考虑拆分统计模块。
5. 每个阶段运行回归测试、类型检查和微信小程序生产构建。

预计按上述小步方案可让主文件减少约 20%–25%。在测试覆盖进一步提高前，不进行整个 `lunch_order` 的全面重构。
